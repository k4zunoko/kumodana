画像も HTML も、
取り消せるリンクで渡す。

kumodana は、自分の Cloudflare に立てる 1 人用の共有棚です。kumo CLI で置けば位置情報を消したコピーに推測できないリンクが付き、取り消せば配信側のキャッシュからも消えます。

GitHub でソースを見る

本番の検証で、位置情報付きの 4.8MB の写真が 4.5 秒でリンクになりました。

リンク 1 本の記録

例
  1. 10:42:07発行kumo put --link有効
  2. 10:43:15Aさんが開くCF-Cache-Status: MISS200
  3. 10:51:40もう一度開くCF-Cache-Status: HIT200
  4. 11:02:13取り消しkumo link revoke取り消し済み
  5. 11:02:16同じ URL を開くこのリンクは使えません404

取り消しから 3 秒で、配信側のキャッシュからも消えています。

保管庫の扉を開けずに、渡す

原本を置いた場所に共有設定を付けると、渡したくないものまで一緒に届きがちです。kumodana は保管庫を持たず、渡すためのコピーだけを並べる棚として作られています。

原本のある場所で共有すると

  • 撮影した場所の GPS が、写真に入ったまま相手に届く
  • 共有をやめても、配信のキャッシュにしばらく残ることがある
  • 送った HTML が、ほかのファイルと同じオリジンで開かれることがある
  • 共有設定が 1 つだと、相手のうち 1 人だけを止められない

kumodana の棚で共有すると

  • 置く前に CLI が位置情報を消す。原本は手元から動かない
  • 取り消すと、エッジのキャッシュもその場で消える
  • HTML は隔離された別のオリジンで開かれ、管理 API に届かない
  • 相手ごとにリンクを発行し、1 本ずつ取り消せる

渡す前と渡したあとに効く、5 つのこと

どれも kumo CLI の 1 行で使えます。数字は本番の検証記録から引いています。

相手ごとに渡して、1 本ずつ止める

1 つのファイルに何本でもリンクを発行でき、メモで相手を見分けられます。取り消しは、記録の無効化とエッジのキャッシュ削除を 1 つの操作で行います。

  • Aさん…/Qm3vR8tZk1Lw0pYc5dHs2A有効
  • Bさん…/f0Xb2nKq7TcVw9LmRz4eYg有効
  • 勉強会の資料…/w7NcE3jLx0QpR5sUa9KdTw取り消し済み

本番では、取り消しの 3 秒後に 404。同じファイルの別のリンクは 200 のままでした。

写真の撮影場所は、相手に届かない

EXIF の位置情報とカメラの情報は、置く前に一時コピーから消します。表示に必要な向きとカラープロファイルは残し、SVG の作者名や手元のパスも取り除きます。

写真のメタデータを棚に置くときの扱いの例
項目元の写真棚のコピー
位置情報35.0116, 135.7681消す
カメラPixel 8消す
向き90° 回転残す
色Display P3残す

本番では、配信された画像に GPS もカメラ情報もなく、原本のハッシュと更新日時も変わりませんでした。

Markdown のメモを、読めるページに

CLI が 1 枚で完結する HTML に変換して置きます。表、タスクリスト、取り消し線に対応し、生の HTML とスクリプトは通しません。

$ kumo preview note.md

HTML のレポートも、隔離して見せる

HTML と SVG は CSP の sandbox で隔離され、origin は null になります。管理用とは別の Worker、別のオリジンから届きます。

本番の隔離チェックで、試した 7 項目をすべて防ぎました。

フォルダではなく、タグで探す

複数のタグで絞り込み、件数付きのタグ一覧で棚の中身を見渡せます。整理の方法をタグ 1 つに絞って、迷わないようにしています。

$ kumo ls --tag 旅行 --tag 2026

3 つの手順で、棚が立つ

Cloudflare 側の設定は、すべて runbook に書いてあります。手で操作するのは最初の 1 回だけです。

  1. 01

    Cloudflare に棚を立てる

    R2 のバケットと D1 のデータベースを作り、管理用の Worker に Cloudflare Access をかけます。デプロイは 1 行です。

    $ npm run deploy
  2. 02

    ブラウザでログインする

    実行するとブラウザが開きます。所有者としてログインすれば、そのあとのトークンは自動で更新されます。

    $ kumo login <管理用の URL>
  3. 03

    置いて、渡して、取り消す

    --link を付けて置けば、推測できない URL が返ります。要らなくなったら、その URL を渡して取り消します。

    $ kumo put note.md --link

書き込みと配信は、別の道を通る

棚に書き込めるのは管理用の Worker だけです。リンクを受け取った人が触れるのは、読むだけの配信用 Worker に限られます。

請求と後始末の心配を、先に片付けておく

kumodana は Workers の無料プランで動かす前提で作られています。上限も止め方も、最初から手順書に入っています。

runbook で手順を読む

  • Workers は無料プランのまま

    EXIF の削除、ハッシュの計算、形式の判定は CLI 側で済ませ、Worker の処理を無料プランの CPU 時間に収めています。

  • 保存量は 8GB で止まる

    上限を超えるアップロードは、使用量、上限、要求サイズを示して拒否します。判定は処理中のものも含めて D1 の上で行います。

  • 配信を止める手順がある

    npm run stop で、Workers を使わずに配信を止められます。本番では約 10 秒で止まり、npm run resume で戻りました。

  • 原本には触れない

    加工は一時コピーに対して行い、終わったら消します。棚から消しても、手元の原本には影響しません。

よくある質問

ここにない疑問は、GitHub の Issues で聞けます。

クラウドドライブの共有リンクと何が違いますか？

kumodana は保管庫ではなく、共有のためだけの棚です。原本は手元に残り、棚には位置情報を消したコピーだけが置かれます。共有はリンク単位で、取り消すと配信側のキャッシュからも消えます。

費用はかかりますか？

Workers は無料プランで動かす前提です。重い処理は CLI 側で行い、Worker の処理を無料プランの CPU 時間に収めています。

R2 は無料枠を超えると課金されるため、保存量はアプリが 8GB で止めます。runbook には予算アラートと緊急停止の手順もあります。

どんなファイルを置けますか？

JPEG、PNG、GIF、WebP、AVIF、SVG、1 枚で完結する HTML、Markdown 文書とテキストです。1 ファイル 100MB 未満で、形式は拡張子ではなく中身で判定します。HEIC は理由を示して拒否します。動画と zip で上げるサイトは対象外です。

リンクに有効期限を付けられますか？

付けられません。リンクは取り消すまで有効です。期限付きリンクと公開の一覧は、方針として作らないと憲法に定めています。相手ごとにリンクを分けておけば、1 本ずつ止められます。

Web の管理画面はありますか？

ありません。操作はすべて kumo CLI で行います。--json を付けると結果を JSON で受け取れるので、スクリプトからも呼べます。

共有した HTML に悪いスクリプトが入っていたら？

配信する HTML と SVG には、allow-same-origin を含まない CSP の sandbox が付きます。ページの origin は null になり、Cookie、localStorage、管理 API、ほかのリンクには届きません。本番の隔離チェックでは 7 項目すべてを防ぎました。

写真の位置情報を残したいときは？

kumo put に --keep-exif を付けます。そのときは位置情報が残ることを警告します。表示に必要な向きとカラープロファイルは、付けなくても残ります。

ログインはどうしますか？

kumo login でブラウザが開き、Cloudflare Access で所有者としてログインします。トークンは自動で更新され、PC をなくしたときは許可を取り消せます。ブラウザのない環境では、CLI 用のサービストークンを環境変数で一時的に使えます。

何人で使えますか？

使うのは所有者 1 人です。見るのはリンクを受け取った人だけで、閲覧者がファイルを一覧できる経路はありません。

検索エンジンに載りますか？

載らないようにしています。配信するすべてのファイルに X-Robots-Tag: noindex と Referrer-Policy: no-referrer を付けます。

始めるには何が必要ですか？

Cloudflare のアカウント（Workers、R2、D1、Access）と Node.js 22.18 以上です。初期設定とデプロイの手順は runbook にまとめてあります。
