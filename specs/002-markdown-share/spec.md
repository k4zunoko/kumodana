# Feature Specification: Markdown 文書を置いてリンクで共有する

**Feature Branch**: `002-markdown-share`

**Created**: 2026-10-19

**Status**: Draft

**Input**: User description: "kumo CLI で Markdown 文書を置いて共有する（CLI で 1 枚完結の HTML に変換し、形式は中身で判定する）"

**関連**: Issue #1、検討資料 [docs/markdown-support.md](../../docs/markdown-support.md)、憲法 v2.1.0。
この仕様は、[001 の spec](../001-share-shelf-mvp/spec.md) の FR-002 と、Edge Cases の「拡張子と中身が違う」を置き換える。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Markdown 文書を置いてリンクで共有する (Priority: P1)

所有者は、手元で書いた Markdown 文書を、画像や HTML と同じコマンドで棚に置き、共有用のリンクを受け取る。
リンクを受け取った人は、ログインなしに、見出し・リスト・表・チェックリストなどが整形されたページを見られる。
文書に紛れ込んだ HTML やスクリプトは動かず、文字として表示される。

**Why this priority**: HTML を書かずに、メモや手順書をそのまま人に見せられることが、この機能の価値そのものである。

**Independent Test**: 表・タスクリスト・取り消し線・URL を含む Markdown 文書を置いてリンクを発行し、ログインしていない
別のブラウザ（PC とスマートフォン）で開いて、記法どおりに整形されていることを確かめる。

**Acceptance Scenarios**:

1. **Given** 手元に `note.md` がある, **When** 所有者がリンク発行付きでそれを置く, **Then** ファイル ID、
   棚に置いた名前 `note.md.html`、判定した形式（Markdown）とリンクが表示され、閲覧者はリンクから整形されたページを見られる
2. **Given** 文書に表、タスクリスト、取り消し線、`https://` で始まる URL がある, **When** 閲覧者がリンクを開く,
   **Then** 表は表として、タスクリストは操作できないチェックボックスとして、取り消し線は線を引いた文字として、URL はリンクとして表示される
3. **Given** 文書に `<script>` や `<img onerror=…>`、`javascript:` のリンクが書かれている, **When** 閲覧者がリンクを開く,
   **Then** HTML は文字として表示され、スクリプトは一切動かず、危険なリンクは働かない
4. **Given** 文書に外部の `https://` の画像と、相対パスの画像がある, **When** 所有者が置く, **Then** 相対パスの画像は表示されない
   ことが警告され、閲覧者には外部の画像だけが表示される
5. **Given** 所有者が文書を置いた, **When** 手元の原本を確認する, **Then** 原本は内容・更新日時ともに変わっていない
6. **Given** 同じ内容の文書をもう一度置く, **When** 置く, **Then** 新たに保存されず、既存のファイルが示される

---

### User Story 2 - 置く前に見え方を確かめる (Priority: P2)

所有者は、棚に置く前に、閲覧者に見えるページを手元のブラウザで確かめられる。確かめたものと、実際に置かれるものは同じである。
確かめるだけなら、管理操作の資格情報もネットワークも要らない。

**Why this priority**: 書き方の崩れや警告に、リンクを渡す前に気づける。共有の失敗を防ぐ。

**Independent Test**: Markdown 文書のプレビューを開き、続けて同じ文書を置いて取得し、両者が同じ内容であることを確かめる。

**Acceptance Scenarios**:

1. **Given** 手元に Markdown 文書がある, **When** 所有者がプレビューを指示する, **Then** 置くときと同じ変換の結果が既定の
   ブラウザで開き、判定した形式と警告が表示される。管理操作は行われない
2. **Given** 所有者が保存先を指定してプレビューする, **When** 指示する, **Then** ブラウザは開かず、変換の結果が指定先に保存される。
   同名のファイルがあれば上書きせず、理由を表示する

---

### User Story 3 - Markdown 以外のテキストを、そのままの形で見せる (Priority: P3)

所有者は、ログ、CSV、JSON、ソースコードなどのテキストを、Markdown として解釈させずに、改行と空白を保った等幅の表示で共有できる。
同じ指定で、HTML や SVG のソースを、ページとしてではなく文字として見せることもできる。

**Why this priority**: 中身で判定する方式では、Markdown でないテキストも Markdown として整形されて崩れる。その逃げ道になる。

**Independent Test**: 複数行のログをテキストとして置き、リンクを開いて、行と空白が元のとおりに表示されることを確かめる。

**Acceptance Scenarios**:

1. **Given** 手元に `app.log` がある, **When** 所有者がテキストとして置くよう指定して置く, **Then** 棚に `app.log.html` として置かれ、
   閲覧者には元の行・空白・記号がそのまま等幅で表示される
2. **Given** 手元に HTML ファイルがある, **When** テキストとして置くよう指定する, **Then** ページとしてではなく、HTML のソースが文字として表示される
3. **Given** 先頭に `<svg>` のロゴを書いた Markdown 文書がある, **When** Markdown として扱うよう指定して置く, **Then** SVG ではなく Markdown 文書として変換される
4. **Given** 画像ファイルがある, **When** テキストまたは Markdown として扱うよう指定する, **Then** テキストではないことを理由に拒否される

---

### User Story 4 - 判定の結果と問題に気づける (Priority: P4)

所有者は、置いたファイルがどの形式として扱われたかを毎回知ることができ、見え方が崩れそうなときや、置けないときには、
理由と対処を示される。

**Why this priority**: 形式は中身だけで決まり、拡張子では決まらない。思い違いに気づける手段が必要である。

**Independent Test**: 拡張子 `.txt` の文書、`.html` なのに先頭が `<div>` のファイル、UTF-16 で保存した文書、秘密鍵を含むテキストを
それぞれ置き、表示・警告・拒否の内容を確かめる。

**Acceptance Scenarios**:

1. **Given** `memo.txt`（中身は普通の文章）がある, **When** 置く, **Then** Markdown として置かれ、拡張子と判定が食い違うこと、
   テキストのまま見せる指定があることが警告される
   （2026-10-23 注記: 見直した。テキスト系の拡張子のテキストは、既定でテキストのまま置かれ、警告は出ない。FR-001 の注記）
2. **Given** UTF-16 で保存した文書がある, **When** 置く, **Then** 何も保存されず、UTF-8 で保存し直すよう案内される
3. **Given** `-----BEGIN … PRIVATE KEY-----` を含むテキストがある, **When** どの指定で置こうとしても, **Then** 何も保存されず、
   秘密鍵が含まれることが表示される
4. **Given** 画像、SVG、HTML（先頭が `<!doctype html>` か `<html>`）がある, **When** 置く, **Then** この機能の追加前と同じ形式として置かれる
5. **Given** 複数のファイルをまとめて置く, **When** 置き終わる, **Then** ファイルごとの判定した形式と、最後に形式ごとの件数と警告の件数が表示される

---

### Edge Cases

- **拡張子と中身が違う**（001 の同じ項目を置き換える）: 形式は中身で判定する。画像・SVG・HTML でないテキストは Markdown として置き、
  拡張子との食い違いを警告する。どれにも当たらなければ拒否する。
  （2026-10-23 注記: テキスト系の拡張子のテキストは、Markdown ではなくテキストのまま置く。FR-001 の注記）
- **先頭に HTML を書いた Markdown（`<p align="center">` など）**: Markdown として置き、HTML は文字として表示し、生の HTML があることを行番号付きで警告する。
- **HTML コメントで始まる Markdown（`<!-- TOC -->` など）**: Markdown として置き、コメントは文字として表示して警告する。
- **先頭が `<!doctype html>` か `<html>` の `.md`**: HTML として置き、拡張子との食い違いを警告する。
- **先頭がインラインの `<svg>` の Markdown**: SVG として判定される。拡張子との食い違いを警告し、Markdown として扱う指定で回避できる。
- **XML 宣言で始まる XML、その他の DOCTYPE（plist など）**: 拒否する。テキストとして置く指定なら置ける。
- **XML 宣言のない XML、`<div>` などで始まる HTML の断片**: Markdown として置き、拡張子の食い違いを警告する。
- **長いコメントの後に `<html>` がある HTML**: コメントの長さにかかわらず HTML として判定する。
- **BOM 付きの UTF-8**: BOM を取り除いて扱う。先頭の見出しは見出しとして表示される。
- **Shift_JIS などの UTF-8 でない文書、UTF-16・UTF-32 の文書**: 拒否し、UTF-8 で保存し直すよう案内する。
- **色付きのログ（端末の制御文字を含む）、NUL を含むファイル**: 拒否し、理由を示す。
- **空のファイル、空白だけのファイル**: 拒否する。
- **PDF**: 拒否する。
- **秘密鍵を含むテキスト**: どの指定でも拒否する。公開鍵は拒否しない。
- **全体が JSON として読めるテキスト**: Markdown として置き、テキストとして置く指定を案内する。
- **元の名前に `.html` を足すと名前の上限（255 文字）を超える**: 元の名前を切り詰めてから `.html` を足す。
- **変換後の大きさが 100MB 以上になる**: 送信前に拒否する。
- **秘密を含むテキスト（秘密鍵以外）を誤って置く**: 置けてしまう。リンクを発行して渡すまでは誰も見られず、削除すれば配信も止まる（受け入れたリスク）。

## Requirements *(mandatory)*

### Functional Requirements

**受け付けと形式の判定**

- **FR-001**: システムは、JPEG、PNG、GIF、WebP、AVIF、SVG の画像、1 枚で完結する HTML、Markdown 文書を受け付けなければならない（MUST）。
  形式はファイルの中身で判定し、ファイル名の拡張子を判定に使ってはならない（MUST NOT）。画像・SVG・HTML のいずれでもなく、
  全体がテキスト（FR-002）であるファイルは、Markdown 文書とみなさなければならない（MUST）。どれにも当たらない場合は、
  理由と受け付ける形式を示して拒否しなければならない（MUST）。
  （2026-10-23 注記: 所有者の決定で見直した。テキストのうち、拡張子がテキストやソースコードのもの（`.txt`、`.log`、`.csv`、`.json`
  など。警告に使う一覧と同じ）は、`--as` の指定がなければ「テキストのまま見せる」（FR-006、FR-012）で置く。拡張子が使われるのは、
  テキストを Markdown として見せるか、そのまま見せるかの既定だけで、受け付けるかどうかと、画像・SVG・HTML・テキストの判定には
  使わない。`.md` などと、拡張子がないもの、一覧にない拡張子のものは、今までどおり Markdown 文書とみなす）
- **FR-002**: テキストとは、BOM と空白を除いて 1 文字以上あり、全体が正しい UTF-8 で、NUL と、タブ・改行・復帰・改ページ以外の
  制御文字を含まないものをいう。UTF-8 の BOM は取り除いて扱わなければならない（MUST）。
- **FR-003**: UTF-16 と UTF-32 のファイル、UTF-8 として正しくないファイル、制御文字を含むファイルは、それぞれの理由と、
  UTF-8 で保存し直すなどの対処を示して拒否しなければならない（MUST）。
- **FR-004**: この機能の追加前に受け付けていた画像・SVG・HTML の判定結果を変えてはならない（MUST NOT）。
- **FR-005**: XML 宣言で始まる XML と、HTML・SVG 以外の DOCTYPE で始まるファイル、PDF は拒否しなければならない（MUST）。
  秘密鍵を含むテキストは、所有者の指定にかかわらず拒否しなければならない（MUST）。
- **FR-006**: 所有者は、テキストを「テキストのまま見せる」か「Markdown として扱う」かを明示できなければならない（MUST）。
  明示は、中身の先頭が HTML・SVG・XML であっても判定より優先する。テキストでないファイルに明示した場合は拒否しなければならない（MUST）。

**変換**

- **FR-007**: Markdown 文書とテキストは、1 枚で完結する HTML に変換してから置かなければならない（MUST）。
  棚に置かれる形式は画像と HTML のままとし、管理操作と配信の仕組みを変えてはならない（MUST NOT）。
- **FR-008**: Markdown 文書は、CommonMark の記法に加えて、表、タスクリスト（操作できないチェックボックス）、取り消し線、
  URL の自動リンクを表示できなければならない（MUST）。単独の改行は、CommonMark どおり改行として扱わない。
- **FR-009**: Markdown 文書の中の HTML（コメントを含む）は、要素として扱わず、文字として表示しなければならない（MUST）。
- **FR-010**: 変換した HTML は、スクリプトを実行させてはならず（MUST NOT）、読み込める外部の資源を `https` の画像だけに
  制限する指定を文書自体に含めなければならない（MUST）。`javascript:` などの危険なリンクは働いてはならない（MUST NOT）。
- **FR-011**: 文書内の画像は、外部の `https` の画像だけを表示する（MUST）。相対パスなどで表示されない画像があれば警告しなければならない（MUST）。
- **FR-012**: テキストのまま見せる指定では、内容を Markdown として解釈せず、すべての文字・空白・改行を保って等幅で表示しなければならない（MUST）。
- **FR-013**: 同じ入力と同じ指定からは、同じ内容の HTML ができなければならない（MUST）。同じ内容は既存のファイルとして扱う（001 の FR-007）。
- **FR-014**: 変換して置くファイルの名前は、元のファイル名の末尾に `.html` を足したものにしなければならない（MUST）。
  足すと 255 文字を超える場合は、元の名前を切り詰めてから足す。変換しない画像・SVG・HTML の名前は変えない。
- **FR-015**: 変換した HTML のページの題名は、Markdown 文書の最初の大見出しとし、なければ元のファイル名としなければならない（MUST）。
- **FR-016**: 変換後の大きさが 100MB 以上になる場合は、送信前に拒否しなければならない（MUST）。
- **FR-017**: システムは、手元の原本を変更・移動・削除してはならない（MUST NOT。001 の FR-005 と同じ）。

**判定結果の表示と警告**

- **FR-018**: システムは、ファイルごとに判定した形式（画像、SVG、HTML、Markdown、テキスト）を結果に表示しなければならない（MUST）。
  他のツールで処理できる形式（JSON）の出力にも含めなければならない（MUST）。
- **FR-019**: 判定した形式が拡張子から想定される形式と異なる場合、全体が JSON として読める場合、文字として表示される HTML がある場合、
  表示されない画像がある場合、外部の画像を読む場合は、警告しなければならない（MUST）。警告は置くことを止めない。
- **FR-020**: 複数のファイルをまとめて置いたときは、最後に形式ごとの件数と警告の件数を表示しなければならない（MUST）。

**プレビュー**

- **FR-021**: 所有者は、管理操作を使わずに、置くときと同じ判定と変換の結果を、既定のブラウザで確かめられなければならない（MUST）。
  ブラウザを開かず、指定した場所に保存することもできなければならない（MUST）。既存のファイルは上書きしてはならない（MUST NOT）。

### Key Entities *(include if feature involves data)*

- **Markdown 文書**: 所有者の手元にある、画像・SVG・HTML のどれでもない UTF-8 のテキスト。棚には置かれず、原本として手元に残る。
- **変換後の HTML**: Markdown 文書またはテキストから作る、1 枚で完結する HTML。001 の「ファイル」として棚に置かれ、
  形式は HTML、名前は元の名前に `.html` を足したもの。
- **判定結果**: ファイルごとの形式（画像、SVG、HTML、Markdown、テキスト）と警告の一覧。表示されるだけで、保存はされない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 表・タスクリスト・取り消し線・自動リンクを含む検証用の文書を置くと、PC の Chrome・Edge・Firefox・Safari と、
  iPhone の Safari・Android の Chrome で、すべての記法が 100% 記法どおりに表示される。
- **SC-002**: スクリプトや危険なリンクを含む検証用の文書を置いたとき、スクリプトの実行と、`https` の画像以外の外部への読み込みの成功数が 0 件である。
- **SC-003**: この機能の追加前に受け付けていた画像・SVG・HTML の判定結果が、追加後も 100% 同じである。
- **SC-004**: 置けないテキスト（UTF-16、UTF-8 でない文書、制御文字、秘密鍵、XML、PDF）では、100% の場合に何も保存されず、理由と対処が表示される。
- **SC-005**: プレビューの結果と、実際に置かれたファイルの内容が 100% 一致する。
- **SC-006**: 1MB の Markdown 文書の変換が、所有者の PC で 2 秒以内に終わる。

## Assumptions

- 利用者は所有者 1 人で、Markdown 文書は所有者が手元のエディタで書く。Web の編集画面は作らない。
- 所有者は文書を UTF-8 で保存する。Windows PowerShell 5.1 の既定（UTF-16）などで保存したものは、案内に従って保存し直す。
- 棚には変換後の HTML だけを置き、Markdown の原文は置かない（憲法 I: 原本は手元）。`get` で取り出すのは HTML である。
- 文書を直したら置き直す。置き直すと別のファイル・別のリンクになり、古いものは所有者が削除する。リンクを保ったままの差し替えは作らない。
- 単独の改行は改行にならない（CommonMark どおり）。行ごとに見せたいテキストは、テキストのまま見せる指定を使う。
- 外部の画像を表示すると、閲覧者の IP アドレスが画像のあるサイトに伝わる。HTML の共有と同じ扱いとして受け入れる。
- 秘密鍵以外の秘密を含むテキストを誤って置くリスクは、リンクを渡すまで誰も見られないことと警告を前提に受け入れる。厳格な確認は作らない。
- 対象外（今回は作らない）: シンタックスハイライト、数式、Mermaid、脚注、見出しのアンカー、生の HTML の部分的な許可、HTML コメントの除去、
  JSON などの自動的なテキスト表示。
