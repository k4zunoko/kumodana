# Feature Specification: 共有棚 MVP（画像と HTML をリンクで共有する）

**Feature Branch**: `001-share-shelf-mvp`

**Created**: 2026-10-15

**Status**: Draft

**Input**: User description: "Cloudflare 上に自分専用の共有用の棚を作る。原本は手元に残し、棚には人に見せる・
渡すためのコピーだけを置く。画像と 1 枚完結の HTML を置いてリンクで共有する。利用者は自分 1 人で、閲覧者は
リンクを受け取った人。公開範囲はリンクの属性で、既定は非公開、リンクは推測できないランダムな URL で、取り消すまで
有効、取り消し可能、1 ファイルに複数発行できる。公開一覧と期限付きリンクは作らない。整理はタグとアルバムで行い、
フォルダは作らない。操作は CLI のみ（put, ls, rm, tag, album, link create, link revoke, link ls）。保存量は
8GB を上限とし、超えたら理由が分かるエラーで拒否する。画像の EXIF は既定で削除し、配信する HTML は隔離して
表示する。配信はキャッシュを使い、リンクが拡散しても費用が増えないようにする。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ファイルを置いてリンクで共有する (Priority: P1)

所有者は、手元の画像または 1 枚で完結する HTML を、コマンド 1 つで棚に置き、そのまま共有用のリンクを
受け取る。リンクを受け取った人は、ログインやアプリのインストールなしに、ブラウザでその画像やページを見られる。
画像の位置情報などのメタデータは、所有者が何もしなくても取り除かれた状態で共有される。

**Why this priority**: 「置いてリンクで渡す」が kumodana の存在理由であり、これだけで価値が成立する。

**Independent Test**: 画像 1 枚と HTML 1 枚を置いてリンクを発行し、ログインしていない別のブラウザ
（PC とスマートフォン）で開けること、画像から位置情報が読み取れないことを確認する。

**Acceptance Scenarios**:

1. **Given** 手元に位置情報付きの JPEG 画像がある, **When** 所有者がリンク発行付きでその画像を置く,
   **Then** ファイル ID と共有用リンクが表示され、リンクを開いた閲覧者には画像が正しい向きで表示され、
   取得した画像に位置情報は含まれない
2. **Given** 手元に 1 枚で完結する HTML がある, **When** 所有者がそれを置いてリンクを発行する,
   **Then** 閲覧者はリンクからそのページを表示でき、ページ内のスクリプトも動作する
3. **Given** ファイルを置いたがリンクを発行していない, **When** 第三者がそのファイルを見ようとする,
   **Then** 閲覧する手段はなく、所有者だけが CLI から取得できる
4. **Given** 所有者が明示的にメタデータを残す指定をした, **When** 画像を置く, **Then** 元のメタデータを
   保ったまま置かれる
5. **Given** 置こうとしたファイルが対象外の形式（動画、HEIC、zip など）である, **When** 所有者が置こうとする,
   **Then** 何も保存されず、対象外である理由と受け付ける形式が表示される
6. **Given** 置いた後も, **When** 所有者が手元の原本を確認する, **Then** 原本は内容・更新日時ともに変わっていない

---

### User Story 2 - リンクを管理し、取り消す (Priority: P2)

所有者は、1 つのファイルに相手ごとのリンクを複数発行し、誰に渡したかのメモを付けておける。
不要になったリンクは個別に取り消すことができ、取り消した後は、そのリンクを知っている人でも見られなくなる。

**Why this priority**: 渡したものを確実に引き上げられることが、安心して共有するための前提になる。

**Independent Test**: 同じファイルに 2 本のリンクを発行し、一方だけを取り消して、取り消したリンクは
開けず、もう一方は開けることを確認する。

**Acceptance Scenarios**:

1. **Given** 置いたファイルがある, **When** 所有者がメモ付きでリンクを 2 本発行する,
   **Then** 異なる 2 本のリンクが発行され、リンク一覧に URL・メモ・作成日時・状態が表示される
2. **Given** 閲覧者が一度開いたリンクがある, **When** 所有者がそのリンクを取り消す,
   **Then** 取り消し完了から 1 分以内に、どの閲覧者が開いても「見つからない」と表示される
3. **Given** 取り消したリンク、存在しないリンク、削除したファイルのリンクがある, **When** 閲覧者がそれぞれを開く,
   **Then** 3 つとも区別のつかない同じ「見つからない」応答になる
4. **Given** 取り消しの反映（配信側の保持データの削除）に失敗した, **When** 取り消しを実行する,
   **Then** 取り消し自体は記録され、反映に失敗したことと再実行の方法が所有者に表示される
5. **Given** リンクの URL に外部サービスが余分な要素（クエリ文字列）を付けた, **When** 閲覧者が開く,
   **Then** 余分な要素のない正規のリンクへ転送され、内容が表示される

---

### User Story 3 - 保存量の上限を守る (Priority: P3)

所有者は、保存量が上限（8 × 10⁹ バイト）を超えることを気にせず使える。上限を超えるアップロードは
保存される前に拒否され、なぜ拒否されたのか（今の使用量、上限、置こうとしたサイズ）が分かる。
所有者はいつでも現在の使用量を確認できる。

**Why this priority**: 保存先は無料枠を超えると自動で課金されるため、費用の上限を仕組みで守る必要がある。

**Independent Test**: 上限を小さく設定した検証環境で、上限を超えるアップロードが拒否されること、
同時に複数アップロードしても合計が上限を超えないことを確認する。

**Acceptance Scenarios**:

1. **Given** 使用量が上限に近い, **When** 所有者が上限を超えるサイズのファイルを置こうとする,
   **Then** 何も保存されず、使用量・上限・要求サイズを含むエラーが表示される
2. **Given** 合計すると上限を超える 2 つのアップロードを同時に行う, **When** 両方が処理される,
   **Then** 上限に収まる方だけが保存され、もう一方は上限超過として拒否される
3. **Given** アップロードが途中で失敗した, **When** 1 時間が経過する,
   **Then** その分の容量は解放され、失敗したファイルは一覧にもリンク発行の対象にも現れない
4. **Given** いくつかのファイルを置いている, **When** 所有者が使用量を確認する,
   **Then** 現在の使用量、上限、残りの容量が表示される

---

### User Story 4 - 棚を整理する（一覧・タグ・アルバム・削除・取得） (Priority: P4)

所有者は、置いたファイルを一覧で確認し、タグやアルバムで整理し、タグやアルバムで絞り込んで探せる。
不要なファイルは削除でき、削除すると関連するリンクもすべて使えなくなる。非公開のファイルも含め、
置いたファイルはいつでも手元に取り出せる。

**Why this priority**: ファイルが増えるほど必要になるが、共有そのものには必須ではない。

**Independent Test**: 複数のファイルにタグを付けてアルバムにまとめ、タグとアルバムで絞り込んだ一覧が
正しいこと、ファイルを削除するとそのリンクが開けなくなり使用量が減ることを確認する。

**Acceptance Scenarios**:

1. **Given** 複数のファイルを置いている, **When** 所有者が一覧を表示する,
   **Then** 新しい順に ID・名前・形式・サイズ・置いた日時・タグ・有効なリンク数が表示される
2. **Given** ファイルがある, **When** 所有者がタグを追加・削除する,
   **Then** 一覧とタグでの絞り込みに反映される
3. **Given** アルバムを作成した, **When** 所有者がファイルを追加・除外する,
   **Then** アルバム内は追加した順に並び、1 つのファイルを複数のアルバムに入れられる
4. **Given** ファイルを含むアルバムがある, **When** 所有者がアルバムを削除する,
   **Then** アルバムだけが消え、中のファイルとリンクは残る
5. **Given** リンクを発行済みのファイルがある, **When** 所有者がそのファイルを削除する,
   **Then** そのファイルのリンクはすべて「見つからない」になり、使用量がそのファイルの分だけ減る
6. **Given** リンクのない非公開のファイルがある, **When** 所有者が取得を指示する,
   **Then** 元のファイル名で手元に保存される

---

### Edge Cases

- **同じ内容のファイルをもう一度置く**: 新たに保存せず、既存のファイルの ID を示す。指定したタグや
  アルバムは既存のファイルに適用する。
- **ファイルが大きすぎる**: 1 ファイル 100MB 以上は、送信を始める前に拒否する。
- **拡張子と中身が違う**: 形式は中身で判定する。中身が対象外なら拒否する。
- **認証情報が無い・期限切れ・誤っている**: 何も変更せず、どの資格情報に問題があるかと対処方法を表示する。
- **ネットワークが途中で切れる**: 不完全なファイルは一覧・リンクに現れず、所有者には失敗したことが表示される。
- **共有した HTML が他の共有ファイルや管理操作に手を出そうとする**: 隔離されているため、何もできない。
- **共有した HTML がブラウザの保存領域（localStorage など）や Cookie を使う**: 隔離のため使えず、
  その部分は動作しない。
- **SVG にスクリプトが含まれる**: HTML と同じく隔離して表示する。
- **リンクが大量に閲覧される**: 同じリンクへの繰り返しの閲覧では保存領域を毎回読まずに返し、費用を増やさない。
  1 日の利用上限に達した場合は、その日の残りは配信と管理操作が止まる（後述の前提を参照）。
- **管理操作が止まっている間に配信を止めたい**: 管理操作を使わずに配信全体を止める手順で対処する。
- **存在しないリンクを総当たりで探される**: 有効なリンクを推測できる確率は実質 0 で、応答から存在の有無も
  区別できない。
- **タグやアルバム名に日本語や空白を使う**: 日本語を使える。前後の空白は取り除き、英字の大文字・小文字は
  区別しない。
- **ファイル名に日本語を含む**: 元のファイル名を保持し、取得時やダウンロード時の名前に使う。

## Requirements *(mandatory)*

### Functional Requirements

**置く（アップロード）**

- **FR-001**: 所有者は、コマンドラインから 1 つ以上の画像または HTML を 1 回の操作で棚に置けなければならない（MUST）。
- **FR-002**: システムは、JPEG、PNG、GIF、WebP、AVIF、SVG の画像と、1 枚で完結する HTML だけを受け付けなければ
  ならない（MUST）。形式はファイルの中身で判定し、対象外の場合は理由と受け付ける形式を示して拒否しなければならない（MUST）。
- **FR-003**: システムは、100MB 以上のファイルを送信前に拒否しなければならない（MUST）。
- **FR-004**: システムは、画像のメタデータ（位置情報、撮影機器の情報など）を既定で取り除いてから置かなければ
  ならない（MUST）。表示に必要な向きの情報とカラープロファイルは保たなければならない（MUST）。所有者が明示的に
  指定した場合に限り、メタデータを残してよい。
- **FR-005**: システムは、手元の原本を変更・移動・削除してはならない（MUST NOT）。
- **FR-006**: システムは、置いたファイルごとに短い ID を割り当て、結果として表示しなければならない（MUST）。
  置くときにリンクの発行、タグの付与、アルバムへの追加を同時に指定できなければならない（MUST）。
- **FR-007**: システムは、同じ内容のファイルがすでに置かれている場合は新たに保存せず、既存のファイルを
  示さなければならない（MUST）。
- **FR-008**: アップロードが途中で失敗した場合、不完全なファイルが一覧やリンク発行の対象に現れては
  ならない（MUST NOT）。その分の容量は 1 時間以内に解放されなければならない（MUST）。

**保存量の上限**

- **FR-009**: システムは、保存量の合計が 8 × 10⁹ バイトを超えるアップロードを、保存する前に拒否しなければ
  ならない（MUST）。判定には処理中のアップロードを含め、同時にアップロードしても合計が上限を超えては
  ならない（MUST NOT）。
- **FR-010**: 上限超過のエラーには、現在の使用量、上限、要求サイズを含めなければならない（MUST）。
- **FR-011**: 所有者は、現在の使用量、上限、残りの容量を確認できなければならない（MUST）。

**リンクと閲覧**

- **FR-012**: ファイルは既定で非公開とし、リンクを持たないファイルは所有者以外が閲覧できてはならない（MUST NOT）。
- **FR-013**: 所有者は、1 つのファイルにリンクを何本でも発行でき、各リンクに任意のメモを付けられなければ
  ならない（MUST）。
- **FR-014**: リンクは 128 ビット以上の乱数を含み、推測できないものでなければならない（MUST）。
- **FR-015**: リンクを知っている人は、ログインなしで内容を閲覧できなければならない（MUST）。画像はブラウザに
  そのまま表示され、HTML はページとして表示されなければならない（MUST）。
- **FR-016**: 共有された HTML と SVG は隔離して表示し、他の共有ファイル、管理操作、Cookie、ブラウザの保存領域に
  アクセスできないようにしなければならない（MUST）。
- **FR-017**: 配信するすべてのファイルについて、検索エンジンに登録しないよう指示し、リンクの URL が参照元として
  外部サイトに送られないようにし、ブラウザが形式を推測して解釈を変えないようにしなければならない（MUST）。
- **FR-018**: 所有者は、リンクの一覧（全体、またはファイルごと）を見られなければならない（MUST）。一覧には URL、
  メモ、作成日時、取り消しの有無を含める。
- **FR-019**: 所有者はリンクを個別に取り消せなければならない（MUST）。取り消し後は、配信側が保持している
  データも含めて、新たな閲覧要求に内容を返してはならない（MUST NOT）。閲覧者のブラウザに残る分も含め、
  取り消しから 1 分以内に誰も閲覧できなくならなければならない（MUST）。
- **FR-020**: 取り消しの反映に失敗した場合、システムは取り消しを記録したうえで失敗を所有者に知らせ、
  反映を再実行できるようにしなければならない（MUST）。
- **FR-021**: 取り消し済み、存在しない、削除済みのいずれのリンクにも、区別できない同じ「見つからない」応答を
  返さなければならない（MUST）。
- **FR-022**: リンクの URL に余分な要素（クエリ文字列）が付いている場合は、内容を返さず、余分な要素のない
  正規の URL へ転送しなければならない（MUST）。
- **FR-023**: システムは、公開一覧、期限付きリンク、閲覧者がファイルを列挙できる手段を提供してはならない（MUST NOT）。

**整理と管理**

- **FR-024**: 所有者は、ファイルを新しい順に一覧でき、タグまたはアルバムで絞り込めなければならない（MUST）。
  一覧には ID、名前、形式、サイズ、置いた日時、タグ、有効なリンクの数を含める。
- **FR-025**: 所有者は、ファイルにタグを複数付け、外せなければならない（MUST）。
- **FR-026**: 所有者は、アルバムを作成・一覧・削除し、アルバムにファイルを追加・除外できなければならない（MUST）。
  アルバム内のファイルは追加した順に並び、1 つのファイルを複数のアルバムに入れられる。アルバムを削除しても
  ファイルとリンクは残る。
- **FR-027**: システムは、フォルダ（階層）を提供してはならない（MUST NOT）。
- **FR-028**: 所有者はファイルを削除できなければならない（MUST）。削除すると、そのファイルのリンクはすべて
  閲覧できなくなり、使用量がそのファイルの分だけ減らなければならない（MUST）。
- **FR-029**: 所有者は、リンクの有無にかかわらず、置いたファイルを元のファイル名で手元に取得できなければ
  ならない（MUST）。
- **FR-030**: 一覧に表示されるファイルは必ず取得・配信でき、一覧に表示されないファイルは配信されてはならない
  （MUST）。棚の内容の変更は、すべて所有者の管理操作を通じて行われなければならない（MUST）。

**管理操作の保護**

- **FR-031**: 管理操作（置く、一覧、削除、タグ、アルバム、リンク、使用量、取得）は所有者だけが行えなければ
  ならない（MUST）。所有者のメールアドレスによるログイン、または所有者が発行したコマンドライン用の資格情報だけを
  受け付け、資格情報はシステムの入口と処理の本体の 2 か所で確認しなければならない（MUST）。
- **FR-032**: 管理操作は、共有されたページなど他のサイトから、ブラウザを経由して実行できてはならない（MUST NOT）。
- **FR-033**: コマンドライン用の資格情報は、所有者の PC 上の設定または環境変数から読み込み、コマンドの出力や
  エラーメッセージに表示してはならない（MUST NOT）。

**コマンドラインの使い勝手**

- **FR-034**: コマンドラインは、置く（put）、一覧（ls）、削除（rm）、タグ（tag）、アルバム（album）、
  リンクの発行・一覧・取り消し（link create / link ls / link revoke）、使用量（usage）、取得（get）を
  提供しなければならない（MUST）。
- **FR-035**: 失敗した操作は、理由と対処が分かるメッセージを表示し、成功とは異なる終了状態で終わらなければ
  ならない（MUST）。各コマンドは、他のツールで処理できる形式（JSON）の出力も選べなければならない（MUST）。

**運用と費用**

- **FR-036**: 同じリンクへの繰り返しの閲覧には、保存領域を毎回読まずに応答しなければならない（MUST）。
- **FR-037**: 所有者は、管理操作が使えない状態でも、配信全体を止められなければならない（MUST）。その手順は
  文書化されていなければならない（MUST）。
- **FR-038**: 利用料金が発生しそうになったときに、所有者へ通知されなければならない（MUST）。

### Key Entities *(include if feature involves data)*

- **ファイル**: 棚に置かれた 1 つの画像または HTML。ID、元のファイル名、形式、サイズ、内容の指紋（同一判定用）、
  状態（処理中／利用可能）、置いた日時を持つ。複数のタグ、複数のアルバム、複数のリンクと関係する。
- **タグ**: ファイルに付けるラベル。ファイルとの多対多の関係で、それ自体は名前だけを持つ。
- **アルバム**: ファイルの順序付きの集まり。ID、名前（重複不可）、作成日時を持つ。ファイルとは多対多で、
  アルバム内での並び順を持つ。
- **リンク**: ファイルを閲覧者に見せるための推測できない URL。トークン、対象ファイル、メモ、作成日時、
  取り消し日時を持つ。1 つのファイルに複数ある。
- **使用量**: 処理中を含む全ファイルのサイズの合計。上限との比較に使う（独立した記録は持たない）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 所有者は、5MB の画像を置いて共有用リンクを受け取るまでを 1 つのコマンドで行え、一般的な
  家庭用回線で 15 秒以内に完了する。
- **SC-002**: リンクを受け取った人は、ログインやアプリなしに、主要なブラウザ（PC とスマートフォンの最新版）で
  初回から 100% 内容を表示できる。
- **SC-003**: 取り消したリンクは、取り消しの完了から 1 分以内に、どの閲覧者からも表示できなくなる。
- **SC-004**: 上限を超えるアップロードは 100% 保存前に拒否され、保存量の合計が上限を超えることは一度もない。
- **SC-005**: 既定の設定で共有した画像から、位置情報が読み取れる割合は 0% である。

  検証用ページを用意し、その試みの成功数が 0 件である。

## Assumptions

- 利用者は所有者 1 人だけで、閲覧者はアカウントを持たない。複数の利用者には対応しない。
- 当面は独自ドメインを持たず、クラウド事業者が提供する共用ドメインで公開する。そのため、一部の企業ネットワークや
  セキュリティ製品では、リンクが開けない可能性がある。独自ドメインへの移行はリンクのトークンを変えずに行える。
- 費用を無料枠に収めるため、1 日あたりの総リクエスト数に上限（約 10 万件）がある。上限に達した日は、
  日付が変わる（日本時間 9 時）まで、配信と管理操作の両方が止まる。
- 同じ内容かどうかは、メタデータを取り除いた後の内容で判定する。
- HTML は 1 枚で完結するものを想定する。外部のサイトから画像やスクリプトを読み込む HTML は、その読み込みが
  そのまま行われる。ブラウザの保存領域や Cookie を使う HTML は、隔離のため正常に動かないことがある。
- 閲覧者のブラウザに残るデータの保持期間は最大 1 分とし、取り消しの反映にかかる時間の上限とする。
- 所有者は自分の PC（Windows）のコマンドラインから操作する。ブラウザ向けの管理画面は作らない。
- 対象外（今回は作らない）: 動画、zip で上げるサイト、アルバムのギャラリーページ、Web の管理画面、
  期限付きリンク、公開一覧、HEIC 形式、複数の利用者。
- 予算の通知と配信の緊急停止は、クラウド事業者側の設定と手順書で実現する。
